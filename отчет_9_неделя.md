# Отчет о проделанной работе: Simple Vault (Anchor / Solana)

**Тема:** Развертывание, анализ и доработка учебного смарт-контракта `simple_vault` на фреймворке Anchor 0.31.1.

**Стек технологий:** Solana, Rust, Anchor, TypeScript, Node.js, `@solana/web3.js`, `@solana/spl-token`.

---

## 1. Диагностика окружения и подготовка репозитория

* **Клонирование репозитория:** Выполнено клонирование проекта с переключением на целевую учебную ветку `students-vault-card`:
```bash
git clone -b students-vault-card https://github.com/0xnurda/vault-dev.git

```


* **Устранение ошибок запуска:**
* Локализована причина ошибки `npm error Missing script: "dev"`: репозиторий представляет собой бэкенд смарт-контракта без фронтенд-сервера разработки, выполнение задач ведется через Anchor CLI и тестовый фреймворк Mocha/Chai.
* Проанализировано несоответствие версий Node.js и пакетов сборки, определен порядок сборки через `anchor build` и `yarn test`.


* **Конфигурация учетных записей:** Определена архитектура аутентификации без использования `.env`-файлов; взаимодействие настроено через локальный ключ Solana CLI (`~/.config/solana/id.json`) и программную генерацию тестовых пар ключей в памяти runtime.

---

## 2. Анализ базового контракта

Изучен исходный функционал протокола, включающий:

1. `initialize_vault` — инициализация состояния пула (`VaultState`), создание PDA хранилища токенов и mint-аккаунта share-токенов.
2. `create_user_card` — создание изолированного аккаунта карточки пользователя (`UserCard` PDA) с сидами `["user_card", vault_state, user]`.
3. `deposit` — перевод пользовательских SPL-токенов в пул с последующим выпуском share-токенов по базовой формуле пропорционального участия.

---

## 3. Выполненные доработки смарт-контракта (`lib.rs`)

### 3.1. Механизм монетизации (Комиссия 1% на депозит)

* Расширена структура аккаунта `VaultState` полем `fee_wallet: Pubkey`.
* В контекст инструкции `Deposit` добавлен аккаунт `fee_token_account` с проверкой владельца (`constraint = fee_token_account.owner == vault_state.fee_wallet`).
* В логику депозита внедрен расчет комиссии: 1% суммы перенаправляется на `fee_token_account`, а доля shares начисляется строго на оставшиеся 99% чистых средств (`net_amount`).

### 3.2. Защита от спама и дробных остатков (Минимальный депозит)

* Введено ограничение `min_deposit` в структуру `VaultState`.
* Добавлен кастомный код ошибки `DepositTooSmall` и строгая проверка `require!(amount >= vault.min_deposit, VaultError::DepositTooSmall)`.

### 3.3. Circuit Breaker (Пауза контракта)

* В структуру `VaultState` внедрен булев флаг `is_paused: bool`.
* Разработана отдельная инструкция `set_paused(ctx, paused: bool)` с авторизацией только от лица создателя пула (`has_one = admin`).
* В инструкцию `deposit` интегрирована блокирующая проверка `require!(!vault.is_paused, VaultError::VaultPaused)`.

## 4. Тестирование и верификация (`tests/vault.ts`)

* Сформирован тестовый сценарий мультипользовательского взаимодействия с участием 3 независимых субъектов (User A, User B, User C):
* Смоделирована последовательность внесения различных сумм токенов с учетом удержания 1% комиссии.
* Проверена точность расчета shares при первом и последующих депозитах:

$$\text{shares} = \frac{\text{net\_amount} \times \text{total\_shares}}{\text{total\_tokens}}$$


* Проверено совпадение суммарного баланса выпущенных долей пользователей со значением `total_shares` в `VaultState`.


* Протестированы негативные кейсы:
* Попытка депозита при активном флаге паузы (`VaultPaused`).
* Попытка депозита суммы ниже установленного порога `min_deposit` (`DepositTooSmall`).
* Попытка повторной инициализации карточки пользователя.
